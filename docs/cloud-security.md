# Проверка Atlas и Netlify — 14 сентября 2026

Проверены настройки через авторизованные интерфейсы аккаунта. Это не внешний пентест.

## Проверено и изменено

- Atlas, проект Project 0, кластер `barbar`: пользователь подключения имеет `readWrite` только на БД `barbar`, роли `atlasAdmin` нет.
- Сетевой список содержит `0.0.0.0/0` с комментарием Netlify и отдельный адрес владельца `/32`. Открытое сетевое правило не отменяет проверку пароля, но позволяет попытки подключения из интернета.
- Вкладка Backup предлагает переход на платный уровень: встроенные копии на текущем бесплатном кластере недоступны. Пользователь выбрал локальные зашифрованные копии; инструкция в `database-backups.md`.
- Netlify: политика секретов для неизвестных fork deploys — Require approval.
- `BARBAR_MONGODB_URI` и `BARBAR_ADMIN_PASSWORD` отмечены Secret.
- **Изменено:** `BARBAR_PASSWORD` также отмечен Secret, значение пароля не менялось. Интерфейс подтвердил Secret values после сохранения.
- Ограничение scopes до Functions недоступно на текущем тарифе: элементы заблокированы и предлагают Upgrade. Секреты доступны в Builds, Functions, Runtime, исключено Post processing.
- Рабочий URI пока присутствует также в трёх тестовых контекстах. Удаление этих значений подготовлено, но **сохранение отклонено автоматической проверкой**; ожидается явное разрешение пользователя. Production URI не изменялся.

- Netlify Production: установлены три BARBAR_PUSH_* переменные, приватный ключ Secret; в других контекстах значений Push нет. Выпуск `0c83731` опубликован, авторизованный интерфейс подтверждает готовность подключения уведомлений. Это не заменяет незавершённые настройки БД ниже.

## Требует завершения

1. Зашифрованная копия **рабочей** БД и её проверка восстановления: автоматическая проверка отклонила выгрузку пользователей/журнала на компьютер и сохранение реквизитов в `.env.backup`; ожидается отдельное подтверждение. Тестовый архив прошёл восстановление.
2. Замена раскрытого пароля Atlas и обновление Netlify URI. Не выполнена. Новые секреты не передавать в чат. Смена пароля требует ручного ввода владельцем в интерфейсе.
3. Подтверждение Production-only URI для `barbar-cafe`: убрать значения из Deploy Previews, Branch deploys, Preview Server & Agent Runners. Этим окружениям затем потребуется собственная тестовая БД и отдельный пользователь.
4. Ограничить Atlas network access фиксированными адресами серверной среды при появлении такой возможности. У стандартных Netlify Functions нет закреплённого за проектом исходящего IP; Private Connectivity — Enterprise add-on. Не удалять `0.0.0.0/0` вслепую: рабочие функции потеряют доступ. Платные услуги не подключались.

## Безопасная смена подключения без остановки сайта

После рабочей резервной копии создать нового пользователя Atlas с ролью `readWrite` только на `barbar` и сильным новым паролем. Пользователь вручную вводит пароль в Atlas. В Netlify заменить только Production-значение `BARBAR_MONGODB_URI`, также обновить приватный файл локального резервирования, затем опубликовать проверенную версию. Проверить вход и чтение реальных данных без тестовых продаж. После подтверждения переключения отключить старое раскрытое подключение. До этого его не удалять: старый deploy ещё использует его.

Для регулярных копий лучше отдельный пользователь `read` на `barbar`. У него не должно быть прав записи или доступа к другим базам. Не хранить рабочие credentials в Deploy Previews или Git.

Официальные ограничения: [Atlas backup](https://www.mongodb.com/docs/atlas/backup-restore-cluster/), [Netlify Private Connectivity](https://docs.netlify.com/manage/security/private-connectivity/).
