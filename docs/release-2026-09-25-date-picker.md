## Что выпускается

- Нативные поля даты браузера заменены календарём из отчётов (`src/barbar/ui/date-picker.tsx`): день продаж (между стрелками дня), «День смены» в закрытии смены, «Годен до» и «Дата» расхода в операциях, «Дата закупки», «Удалить историю раньше» в бэкапах. В `src` больше нет `type="date"`.
- Ограничения прежние: продажи, смена и расход — не позже рабочего дня (`businessToday()`), закупка и бэкапы — не позже `today()`, «Годен до» — не раньше рабочего дня. Значения — строки `YYYY-MM-DD`.
- «Годен до» необязателен: пустое значение показывается как «Не указан», есть кнопка «Очистить»; пустой срок не отправляется.
- Внутри окна календарь открывается отдельной шторкой поверх, Escape закрывает только его. Вне окон всплывающая панель позиционируется относительно экрана, поэтому прокручиваемая панель продаж её не обрезает. На телефоне календарь открывается снизу на всю ширину.
- `Sheet` останавливает событие `cancel`, чтобы Escape во вложенной шторке не закрывал родительское окно; у шторок появилось доступное имя по заголовку.
- `Reports.tsx` и `PeriodComparison.tsx` не менялись.
- Миграций и изменений API нет.

## Проверки до публикации

По указанию владельца («залей на прод без тестов») автоматические тесты перед этим выпуском **не запускались**: `npm test`, `npm run test:e2e`, `test:db`, `test:backup`, `test:scheduled-backup`. Это отступление от обычного порядка `barbar-release`.

Выполнена только сборка для публикации `npm run build` (ESLint `--max-warnings 0`, photo manifest, `tsc -b`, Vite). 25 сентября она прошла на этапе разработки и повторно на этапе выпуска перед push, не изменив отслеживаемые файлы. `dist/index.html` ссылается на `main-CYqiwLg5.js` и `main-Cf8Gmh_p.css`; CSS содержит `.date-picker-panel.in-sheet` и `.date-control .date-picker-trigger`. Если перед push что-то изменится, этап выпуска пересобирает проект и сверяет имена заново.

Историческая справка, не проверка этой ревизии: на этапе разработки по этим изменениям локально проходили полный Playwright (140/140) и проверка типов. Не доказано, что эти прогоны шли по итоговой ревизии файлов, поэтому они её не подтверждают.

## Ограничения и ручная проверка

- Не проверено автоматически: календарь во вложенных окнах (особенно iOS Safari, окно поверх окна) и на узком экране.
- Проверку под ролями на production владелец выполняет вручную, без создания операций:
  - продажи: выбор дня, стрелки;
  - закрытие смены;
  - операция: «Годен до» с очисткой и дата расхода;
  - закупка;
  - «Удалить историю раньше» в бэкапах, без подтверждения удаления.
- Изменения тестов (`tests/fixtures.ts`, `barbar.spec.ts`, `session-filters.spec.ts`) в итоговом виде не запускались и будут проверены следующим полным прогоном.
