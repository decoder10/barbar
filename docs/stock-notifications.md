# Уведомления об остатках

## Поведение

- Внутри приложения включены автоматически для владельца и рабочего. Отдельное разрешение браузера не требуется; выводятся только название, количество и единица.
- Порог низкого остатка: 3 бутылки; для мл/г — три самые большие порции ингредиента из сохранённых рецептов. Без рецепта для мл/г нет выдуманного порога: предупреждаем только при нуле.
- Переход нормальный → низкий и положительный → ноль даёт предупреждение. Повторные продажи в том же состоянии не спамят. Пополнение снова разрешает переходы и снимает устаревшее предупреждение.
- Первый вход не создаёт десятки предупреждений по ранее пустому складу. Открытые устройства узнают об изменении через существующее обновление состояния; у продавца — сразу после ответа продажи.
- Системный push включается кнопкой «Уведомления» → «Включить push на этом устройстве». Разрешение запрашивается только после нажатия. Выключение удаляет подписку сервера и браузера.
- Когда приложение видно, heartbeat раз в минуту отмечает устройство активным на 90 секунд; при скрытии/закрытии отправляется keepalive-сообщение. Таким устройствам push не отправляется, предупреждение показывает приложение. При аварийном закрытии без pagehide возможна задержка перехода в фоновый режим до 90 секунд.
- Подписка привязана к текущему сеансу (до 12 часов), а не к паролю. Выход, истечение сеанса, блокировка или смена authVersion прекращают доставку. При новом входе разрешённая подписка браузера привязывается к новому сеансу.
- На iPhone/iPad нужен запуск установленного веб-приложения с экрана «Домой» и поддерживаемая версия iOS; обычной вкладки недостаточно.

## Сервер и ограничения доставки

`recordStockAlerts` сохраняет событие в той же MongoDB-транзакции, что и продажу. ID команды — ID события, поэтому повторы не создают дубликаты. Проверка одинаковая для быстрого и исторического пути записи. Список содержит только поля StockAlert, без финансовых данных.

Отдельная очередь `stockAlertEvents` имеет lease, отметки обработанных устройств, максимум 5 попыток и TTL 24 часа. Отправка идёт после успешной операции; её ошибка не откатывает продажу. Netlify scheduled function каждые 5 минут подбирает незавершённую очередь. Одновременно не более 5 отправок, бюджет прохода около 6 секунд плюс завершение текущей группы. При отсутствии ключей отправитель сразу выходит. Старше 10 минут события не отправляются; push TTL 5 минут — предупреждение не должно приходить через сутки с устаревшим остатком. Это best-effort доставка, а не гарантированное SMS.

Один проход обрабатывает событие и максимум 100 устройств (не более 10 на пользователя). Удаляются истёкшие/недействительные подписки и ответы push-сервиса 404/410. Повторы после сетевой неопределённости используют один notification tag. В foreground ошибка/обрыв heartbeat может дать лишний системный push; это не повторная продажа.

API `/api/barbar/push` требует действующий сеанс и same-origin для всех записей. Сервер принимает только HTTPS endpoints известных сервисов Chrome/Firefox/Safari, проверяет формат ключей, не возвращает подписки других пользователей. Перед доставкой повторно проверяются сеанс, активность и authVersion. Service worker не кеширует сайт, API и данные пользователей; клик открывает только `/inventory`.

`pushDevices` и `stockAlertEvents` — временные данные; зашифрованные резервные копии их исключают, как и сеансы. Индексы: TTL устройств, userId для лимитов, TTL событий, done+nextAttempt для очереди. Основной журнал не сканируется ради push.

## Включение

1. Один раз запустить `node scripts/push-keys.mjs`. Скрипт создаёт `.env.push` с правами 0600 и отказывается перезаписывать существующий файл. Файл исключён из Git, ключи не печатаются. Локальный API читает его при старте; перезапустить dev server после создания.
2. Для production перенести из этого файла в серверные переменные Netlify: `BARBAR_PUSH_PUBLIC_KEY`, `BARBAR_PUSH_PRIVATE_KEY`, `BARBAR_PUSH_SUBJECT`. Приватный ключ пометить Secret. Не использовать префикс VITE_ и не добавлять ключи в Git. Subject — URL бара или контактный mailto.
3. После разрешённого deploy включить уведомления в приложении на нужных устройствах. Проверить реальное получение на отдельном тестовом товаре/окружении; рабочие продажи для проверки не создавать.
4. Не менять VAPID-пару при каждом deploy: существующие подписки привязаны к ключу. При ротации устройств потребуется повторное подключение.

14 сентября 2026: VAPID-пара установлена в Netlify только для Production, приватный ключ отмечен Secret. Выпуск `0c83731` опубликован; авторизованный интерфейс подтверждает готовность подписки, `barbar-push-retry` зарегистрирован с расписанием каждые 5 минут. Разрешение браузера и фактическое получение системного push ещё не подтверждены. Рабочие продажи для теста не создавались. Подробности: [проверка выпуска](release-2026-09-14-production.md).
