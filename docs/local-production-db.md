# Локальный запуск с рабочей БД Production

Отдельный, явно выбираемый режим: локально запущенное приложение читает и **записывает** рабочую базу бара. Все продажи, закупки и правки сохраняются по-настоящему.

## Настройка (один раз)

```sh
cp .env.production-db.example .env.production-db
chmod 600 .env.production-db
```

В `.env.production-db` указать строку подключения Atlas в `BARBAR_PRODUCTION_MONGODB_URI` и при необходимости имя базы в `BARBAR_PRODUCTION_MONGODB_DATABASE` (по умолчанию `barbar`). Строку вставлять только в этот файл, не в чат и не в Git: файл исключён из Git правилом `.env.*`.

Atlas → кластер → Connect → Drivers показывает адрес с `<db_password>`. Оставьте этот маркер и укажите пароль **пользователя базы данных** в `BARBAR_PRODUCTION_MONGODB_PASSWORD` в том же файле. Приложение само URL-кодирует специальные символы. Это не пароль Google или сайта Atlas. Если URI уже содержит закодированный пароль, отдельное поле можно оставить пустым. Существующий пароль Atlas и Secret в Netlify прочитать обратно нельзя.

Для чтения лучше отдельный пользователь Atlas. Для работы нужен пользователь с `readWrite` только на `barbar`.

## Запуск

```sh
npm run dev:production-db
```

- Сервер открывается на **http://127.0.0.1:4002** — другой порт, чем обычный `npm run dev` (4001). Браузерные тесты работают только с 4001.
- В терминале выводится предупреждение, в приложении — красная полоса «Рабочая база Production» на всех экранах, включая вход.
- Строка подключения читается только сервером из `.env.production-db`. В `process.env`, клиентский код и переменные `VITE_` она не попадает.
- До открытия порта сервер проверяет соединение и наличие рабочей базы. Ошибки пароля, прав и сети показываются без URI и секретов; при сбое переключения на локальную БД нет.

## Что режим не делает

- Не создаёт пользователей из локального `.env` и не меняет существующие учётные записи.
- Не импортирует и не заполняет данные, не запускает миграции и не добавляет позиции каталога. Если рабочей базе нужна миграция, API отвечает ошибкой «Эта база требует миграции…»: запустите опубликованную версию.
- Не используется тестами: `npm test` и `npm run test:db` работают с локальной тестовой MongoDB (`test:db` проверяет, что адрес локальный), Playwright — с портом 4001.

Уведомления push из этого режима уходят реальным устройствам владельца, если в `.env.push` те же ключи, что в Netlify.

## Возврат к локальной или тестовой базе

Остановить сервер (Ctrl+C) и запустить обычный режим:

```sh
npm run db:start
npm run dev
```

Обычный режим использует `BARBAR_MONGODB_URI` из `.env` или локальную MongoDB `127.0.0.1:27017`.

## Проверки

- `server/database-profile.test.ts`: режим включается только явным `BARBAR_LOCAL_DATABASE=production`; файл обязателен и должен иметь права 0600; локальный адрес вместо Atlas отклоняется; строка подключения не попадает в `process.env`.
- Запуск без файла останавливает dev-сервер с сообщением «Создайте .env.production-db…» (проверено).
