# Настройки бара без изменения кода

Группы склада, категории меню, тексты гостевого меню, миграции каталога и готовые значения в формах лежат в JSON-файлах `src/barbar/config/`. Код читает их через `src/barbar/config/index.ts`. Чтобы переименовать группу, добавить слово для распознавания продукта или поменять порядок разделов гостевого меню, код менять не нужно.

После любой правки выполните `npm run test:unit`. Тест `src/barbar/config/__tests__/config.test.ts` проверяет, что конфигурация согласована. Например: все группы из `matchOrder` существуют, регулярные выражения компилируются, у текстов есть RU/EN/HY, у подписей есть переводы. С ошибкой в конфиге сборка не проходит проверку.

## Файлы

| Файл | Что настраивает |
| --- | --- |
| `inventory-groups.json` | Группы склада: название, подсказка под вкладкой, учётная категория новой позиции (`mixer`, `food`…), единица по умолчанию, единица и раздел меню для «товара целиком», слова для распознавания по названию. `matchOrder` — порядок проверки слов, `recipePicker` — какие группы и в каком порядке показываются в выборе ингредиентов для напитков и закусок, `fallbackGroup` — группа для всего нераспознанного. |
| `menu-categories.json` | Категории меню: название, показ в «Меню и рецептах» (`recipes`), блок «Дополнительные расходы на порцию» (`extraCosts`), выбор продуктов кухни вместо барных ингредиентов (`foodRecipe`), листы фотографий в редакторе, заголовок в гостевом меню на трёх языках. `sets` — категория сетов, категория их составляющих и пределы. |
| `catalog-upgrades.json` | Одноразовые обновления каталога в базе: пункты бумажного меню, которые продаются целиком, со стартовой единицей; дубли склада, удаляемые без истории; объединения (Тоник → Tonic и т.п.) с объёмом одной продажи. |
| `guest-menu.json` | Порядок разделов, языки, порция крепкого (`{ml}` в заголовке заменяется объёмом), все тексты страницы `/menu`. |
| `presets.json` | Кнопки объёмов бутылки и бокала, кнопки фасовки (`packSizes`: мл/г и штуки), быстрые количества в закупке (`packs` — число фасовок), сколько дней до срока партия считается «скоро», размер страницы карточек, период подсчёта самых продаваемых позиций (`popularityDays`, дней до выбранного дня включительно), лимит и порог предупреждения хранилища Atlas (читают и скрипты `db:storage`, `db:backup:scheduled`). |

## Слова для распознавания

Слово — это часть названия в нижнем регистре: `"сок"` найдёт «Томатный сок». Для точных правил используется префикс `re:` и регулярное выражение, например `"re:(^|\\s)лук"`. В JavaScript `\b` не работает с кириллицей, поэтому для русских слов используйте основу без `\b`. Группа, выбранная владельцем в карточке позиции, всегда важнее распознавания.

## Миграции каталога

Ключ миграции товаров и объединений содержит хеш соответствующего раздела `catalog-upgrades.json`. После изменения списка миграция один раз выполнится заново при первом запросе к базе. Миграции ничего не делают, если изменений нет: позиции с продажами, закупками, рецептами или остатком не удаляются и не переписываются. Прежде чем менять этот файл для рабочей базы, сделайте резервную копию (`npm run db:backup`).

## Что остаётся в коде

- Учётные категории (`alcohol`, `mixer`, `beer`, `wine`, `cognac`, `food`, `goods`) и единицы (`ml`, `g`, `bottle`, `pcs`). От них зависят проверки журнала и расчёт себестоимости. Тест сверяет категории меню в конфиге со списком, который понимает журнал.
- Правила выбора фотографий по названию (`features/catalog/media/photo-catalog.ts`) и источники фото (`public/barbar/photos/sources.json`).
- Переводы интерфейса (`presentation/i18n/*.json`). Названия и подсказки из конфигов переводятся через те же словари.

## Значения по умолчанию для закупок

Срок поставки (3 дня) и страховые дни (4) — поля формы «Прогноз закупок» и параметры `lead`/`reserve` отчёта; они действуют, пока срок не задан у позиции или поставщика и страховые дни — у позиции. Поставщики, сроки и страховой запас заполняет владелец в «Параметры закупок»; пустое значение означает «не задано», данные не придумываются. Фактические выходы и потери партий вводятся при выпуске заготовки; прежние партии показываются как «план не указан».
