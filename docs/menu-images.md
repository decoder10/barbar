# Фотографии каталога

Изображения хранятся локально в `public/barbar/photos`, без внешнего hotlink. Источники, авторы и лицензии перечислены в `sources.json` и публичной странице `credits.html` (ссылка внизу навигации).

Для марок используются фотографии производителей и Wikimedia Commons. Часть снимков обработана imagegen для удаления окружения; такие изменения отмечены в атрибуции. Изображение показывает марку, а объём конкретной позиции задаётся данными склада.

Для неизвестной упаковки созданы основы `generated-beer.webp` и `generated-wine.webp`; название позиции накладывается на этикетку средствами интерфейса. Это условные изображения, а не точные фотографии упаковки производителя. Примеры подачи напитков также не являются фотографиями фактического рецепта бара.

`src/barbar/features/catalog/media/photo-catalog.ts` выбирает изображение по марке, категории и подаче: бутылка и бокал вина отличаются, вкусы пива не подменяются фруктами. Старые числовые ID изображений рецептов сохраняются, но отображают новые фотографии. Карточки используют `object-fit: contain`; склад показывает более крупные миниатюры. Старые атласы остаются для совместимости ресурсов, интерфейс их больше не использует.

## AVIF, адаптивные размеры и кеш

`npm run photos:optimize` готовит AVIF (quality 55, 4:4:4) и WebP (quality 80) шириной 160, 320 и до 640 px, без увеличения исходника и без обрезки. Логотип и основы условных бутылок также оптимизируются. Исходники и атрибуция сохраняются. Настройки кодека: [Sharp output](https://sharp.pixelplumbing.com/api-output/#avif).

Компонент `CatalogImage` использует `<picture>`, AVIF с WebP fallback, `srcset`, размеры `auto` для ленивых изображений и явно заданную геометрию. Браузер выбирает размер по месту в интерфейсе и плотности экрана; в браузерах без автоматических размеров действует запасное правило `sizes`. Логотип загружается сразу. SVG-основы условных бутылок используют оптимизированный WebP для совместимости SVG image.

В именах готовых файлов находится хеш содержимого. `netlify.toml` задаёт для `/barbar/photos/optimized/*` годовой `Cache-Control: public, max-age=31536000, immutable`. Это позволяет повторно использовать фото при переходах и перезагрузках; замена изображения меняет URL. Заголовок заработает после публикации на Netlify. HTML и персональные API этим правилом не кешируются.

Исключение — свои фото владельца (T11, с 25 сентября 2026, не опубликовано): их кодирует функция загрузки при сохранении (WebP 160/320/640 без метаданных), файлы хранятся в Netlify Blobs, а не в Git, и показываются вместо примера без пометки «Пример». Подробности — в [guest-menu.md](guest-menu.md#собственные-фотографии-позиций-t11).

Кодирование библиотеки выполняется локально, не в Functions и не при каждом деплое. Готовые файлы и `optimized/variants.json` входят в Git. Повторный запуск пропускает неизменившиеся исходники; build проверяет соответствие исходников манифесту и просит запустить оптимизацию, если фото изменилось. Старые файлы с хешами автоматически не удаляются.

Замер 14.09.2026: 160 фотографий каталога — 5 932 174 → 2 280 141 байт (−62%) для самых крупных вариантов, обычно до 640 px. Вместе с логотипом и двумя основами: 163 изображения, 6 436 753 → 2 310 475 байт (−64%). Это сумма одного выбранного крупного варианта на изображение, а не размер всей папки со всеми форматами и исходниками. Маленькие варианты уменьшают фактическую загрузку дополнительно. В этой выборке AVIF меньше WebP для всех изображений; генератор сравнивает форматы заново при изменениях.

Проверены хеши, доступность и размеры всех вариантов, AVIF в браузере, WebP fallback, адаптивная раскладка, `contain` и отсутствие смещения при наведении. Ускорение именно рабочего Netlify ещё требует публикации и замера на рабочем сайте.
