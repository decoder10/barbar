# Хранилище MongoDB: оценка и варианты — 15 сентября 2026

Оценка без подключения платных услуг и без переноса рабочей БД.

## Что известно сейчас

- По скриншоту Atlas владельца: **143,51 MB из 512 MB (28%)**, бесплатный кластер Free (M0).
- Рабочие реквизиты Atlas в проекте не хранятся, поэтому разбивку по базам, коллекциям и индексам нужно снять на компьютере владельца готовым инструментом (только чтение):

```sh
npm run db:storage
```

Команда берёт строку подключения из `.env.backup` (достаточно пользователя Atlas с ролью `read` на `barbar`) и выводит: размер данных и индексов, процент от лимита, размеры каждой коллекции и её индексов, список доступных пользователю баз, количество новых продаж, закупок, операций, расходов и событий журнала за 30 и 90 дней, оценку прироста в MB в месяц и сколько месяцев осталось до лимита. Документы и пароли не выводятся. Проверено на локальной MongoDB.

Автоматические копии (`npm run db:backup:scheduled`) теперь записывают ту же краткую сводку в `.barbar-backups/last-run.json` и помечают `storageWarning`, если заполнено 70% и больше.

## Как Atlas считает место и что будет при заполнении

По документации Atlas для Free-кластера:

- Лимит **0,5 GB — жёсткий**. В него входят несжатые BSON-документы всех коллекций **плюс их индексы** ([Free Cluster Limits](https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/)). Поэтому цифра в Atlas больше, чем размер файлов резервной копии.
- При попытке записи сверх лимита Atlas отвечает ошибкой `8000 you are over your space quota` ([Storage FAQ](https://www.mongodb.com/docs/atlas/reference/faq/storage/), [Write-Blocking](https://www.mongodb.com/docs/atlas/cluster-blocking-writes/)). Чтение остаётся доступным.
- **Что перестанет работать в баре:** запись продаж, закупок, списаний и расходов, правки меню и склада, журнал действий, очередь уведомлений. **Вход тоже перестанет работать**: каждый вход создаёт запись сеанса. Уже сохранённые данные не теряются, но работать с приложением будет нельзя, пока место не освободят или не перейдут на тариф больше.
- Другие ограничения Free: 100 операций в секунду, 500 соединений, 10 GB входящего и 10 GB исходящего трафика за 7 дней, пауза кластера после 30 дней без соединений, встроенных резервных копий нет.

## Вероятные причины расхода (проверить отчётом)

1. **Индексы.** У каждой коллекции есть служебный `_id` и индексы под отчёты и историю. На маленькой базе индексы занимают больше места, чем сами данные: локально при 116 позициях каталога индексы — 0,75 MB, данные — 0,07 MB.
2. **Журнал действий `auditEvents`.** Одно событие на каждую операцию, растёт вместе с продажами.
3. **Продажи `sales`.** Каждая хранит неизменный снимок ингредиентов и себестоимости.
4. **Отдельные базы Deploy Preview.** Приложение для предпросмотров использует базы `barbar_preview_<deploy>`. Они занимают место того же кластера, если у пользователя подключения есть на них права. Отчёт покажет их в `databases`.
5. Сеансы и очереди уведомлений (`sessions`, `pushDevices`, `stockAlertEvents`, `purchaseEvents`) удаляются автоматически по сроку и обычно малы.

## Контроль заполнения

- Запускать `npm run db:storage` раз в месяц или включить автоматические копии: сводка будет в каждом запуске.
- В Atlas: Project → Alerts. Проверить, доступно ли для Free-кластера оповещение по размеру данных, и настроить 70% и 85%. Если такого оповещения нет, опираться на сводку копий.
- Порог действий: **70%** — удалить лишние базы предпросмотра и решить вопрос с историей; **85%** — перейти на тариф больше, не дожидаясь ошибки записи.

## Как уменьшить объём, сохранив историю учёта

- Удалить старые базы `barbar_preview_*`, если они есть. Это единственное безопасное удаление: рабочий учёт в них не хранится.
- Перед любой очисткой делать зашифрованную копию и проверку восстановления (`npm run db:backup`, `npm run db:verify`, `npm run db:restore`).
- Архивация старых продаж уже есть в «Данные и копии»: из базы удаляются отдельные записи до выбранной даты, а итоговые остатки и себестоимость сохраняются. Полная история остаётся в зашифрованных копиях.
- Журнал действий: при необходимости можно ввести срок хранения (например, 12 месяцев в базе, остальное — в копиях). Сейчас не реализовано, нужно отдельное решение владельца.
- Не удалять индексы вручную: они нужны отчётам и истории.

Точный тариф из проекта проверить нельзя: нужен вход в аккаунт владельца. Как проверить:

1. Открыть [payments.google.com](https://payments.google.com) → «Подписки и услуги».
2. Если там **Google One** (100 GB, AI Plus и т.п.), это хранилище для Drive, Фото и Gmail ([планы Google One](https://one.google.com/about/plans)). **Размещения базы данных в нём нет.** Зато его удобно использовать как второй носитель для зашифрованных копий: указать папку Google Drive для компьютеров в `BARBAR_BACKUP_MIRROR_DIR`.

## Рекомендация

1. **Сейчас оставаться на Atlas Free.** 28% — запас есть. Снять отчёт `npm run db:storage`, удалить лишние базы предпросмотра, если найдутся, и включить автоматические копии со сводкой.
2. При заполнении **70%** или если отчёт показывает меньше 6 месяцев до лимита — **перейти на Atlas Flex**: код менять не нужно.
3. Другие бесплатные сервисы не дают выигрыша без риска: нужна проверка транзакций или переделка хранилища.

## План переноса на другой кластер (если понадобится)

1. Создать новый кластер и пользователя `readWrite` только на `barbar`; сетевой доступ как у текущего.
2. Вечером после закрытия бара: `npm run db:backup`, затем `npm run db:verify`.
3. Восстановить копию в новый кластер в базу `barbar` (адрес назначения указать в `BARBAR_RESTORE_MONGODB_URI`) и сверить количество документов с отчётом копии.
4. Проверить приложение локально на новом кластере в режиме `npm run dev:production-db` без записи продаж: вход, остатки, отчёты.
5. В Netlify заменить Production `BARBAR_MONGODB_URI`, опубликовать, проверить вход и чтение данных.
6. Старый кластер оставить без изменений на 7 дней. **Откат** — вернуть прежний URI в Netlify и опубликовать. Записи, сделанные на новом кластере за это время, переносятся отдельной копией.
7. После недели стабильной работы удалить старое подключение.
