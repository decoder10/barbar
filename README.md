# Barbar Cafe · Art Gallery

Самостоятельное приложение на **React + TypeScript + Node.js** для меню, закупок, рецептов, продаж и отчётов. Портфолио — другой проект; файлы Barbar находятся только в этом репозитории.

## Локальный запуск

Требуется Node.js **22.12+** (или Node.js 24).

```sh
npm ci
npm run dev
```

Открыть **http://localhost:4001**. React и Node API запускаются одной командой. Порт фиксирован: занятый порт вызывает ошибку, приложение не переключается незаметно на другой.

Перед первым запуском скопируйте `.env.example` в `.env` и задайте `BARBAR_PASSWORD` (от 12 символов). Логин по умолчанию — `barbar`. На настроенном компьютере владельца `.env` уже создан с согласованным паролем. Этот файл исключён из Git. Демо-режима и фиктивных закупок в приложении нет.

Локальные рабочие данные находятся в `.barbar-data/`, игнорируются Git и не отправляются в репозиторий. Не удаляйте эту папку для очистки истории: используйте страницу **«Файлы и копии»**, чтобы сохранить остатки.

## Netlify

1. Создать новый проект Netlify, подключить GitHub-репозиторий `decoder10/barbar` и выбрать ветку с проектом.
2. Настройки уже записаны в `netlify.toml`: build command `npm run build`, publish directory `dist`, functions directory `netlify/functions`, Node.js 22.
3. В Environment variables установить **`BARBAR_PASSWORD`** (от 12 символов, область Functions) и при желании **`BARBAR_USERNAME=barbar`**. Пароль передавать только серверу: не добавлять префикс `VITE_`. Для начального входа можно использовать согласованный тестовый пароль; для рабочего бара задайте собственный.
4. Выполнить deploy. Войти с указанными серверными данными. Без `BARBAR_PASSWORD` сервер закрыт и показывает инструкцию по настройке.
5. Добавить свой домен или поддомен, например `barbar.arams.website`, через Domain management. Приложение открывается от корня своего домена; портфолио остаётся на прежнем домене. Прямые переходы `/inventory`, `/cocktails`, `/reports`, `/files` поддерживаются.

Просто загрузить папку `dist` через drag-and-drop недостаточно для общего учёта: нужны задеплоенные Node Functions. Подключение Git-репозитория обеспечивает сборку обоих слоёв.

Данные автоматически сохраняются в **Netlify Blobs**. Используется site-wide store `barbar-cafe-v1`: он переживает новые deploy. Предпросмотры используют отдельное хранилище по ветке, чтобы не менять рабочий бар. Локальные данные не загружаются в Netlify автоматически: для переноса скачайте полную резервную копию локально и восстановите её на сайте.

Документация платформы: [хранилище и условные записи](https://docs.netlify.com/build/data-and-storage/netlify-blobs/), [маршрутизация Node Functions](https://docs.netlify.com/build/functions/configuration/), [ограничение попыток входа](https://docs.netlify.com/manage/security/secure-access-to-sites/rate-limiting/).

## Рабочий порядок

1. **Склад:** при необходимости создать ингредиент. Для алкоголя/жидкостей — миллилитры и цены за 1 000 мл. Для фруктов, сахара и специй — граммы и цены за 1 000 г. Затем добавить закупку с количеством, датой и фактической ценой. 1 000 + 1 000 = 2 000 единиц на складе.
2. **Меню и рецепты:** выбрать позицию, нажать карточку, добавить состав на одну продаваемую порцию. Для настойки указывается расход алкоголя, ягод, сахара и других ингредиентов на порцию; для сета — на полный сет. Это расчёт расхода на продажу, без отдельного производственного учёта партий настоек.
3. **Себестоимость** вычисляется из состава по средней стоимости оставшегося запаса. **Цена продажи** — отдельное редактируемое поле. Кнопка расчёта с наценкой лишь предлагает цену; её нужно применить явно. Изменение закупочных цен само по себе продажную цену не меняет.
4. **Продажи:** выбрать дату, нажать карточку, ввести число порций либо миллилитры алкоголя в розлив. Сервер проверит остатки и запишет продажу вместе со списаниями. Пустой состав блокирует продажу позиции меню. Недостаток ингредиентов и продажи до закупки запрещены.
5. **Отчёты:** день или месяц, выручка, стоимость проданных ингредиентов, валовая прибыль, закупки, продажи по позициям и расход ингредиентов. Часовой пояс — Ереван, валюта — AMD ֏. CSV содержит строки продаж, включая отметки об отменах; отмены исключены из итогов.

Историческая продажа хранит название, категорию, состав, сумму выручки и стоимость каждого списания. Редактирование рецепта или прайс-листа не меняет прошлые отчёты. Отмена продажи возвращает ингредиенты и их стоимость на склад.

Валовая прибыль = выручка − ингредиенты. Аренда, зарплаты, налоги и другие расходы не включены.

## Меню и изображения

В `src/barbar/data/cocktails.json` внесены **167 позиций и вариантов** из предоставленного меню: коктейли, настойки, шоты, сеты, пиво, закуски, горячие и безалкогольные напитки, вина. Название файла сохранено для совместимости с исходной моделью, в интерфейсе это «Меню и рецепты».

Продажные цены внесены с фотографий. Составы не выдуманы и по умолчанию пусты: заполните их через редактор. Цены напитков из раздела **50 ML** пересчитаны в прайс за 1 000 мл умножением на 20. Парные цены вин разнесены на «бокал» и «бутылка»; фактические объёмы нужно указать в рецепте. `Your cocktail` имеет нулевую цену, которую надо задать вручную. У `Sujuck` на фото есть рукописная правка: внесено 1 500 ֏, эту строку следует сверить.

Фотографии карточек иллюстративные, выбираются в редакторе из 12 вариантов. Логотип восстановлен по предоставленной вывеске. Исходная фотография стены/вывески не используется на сайте и не включена в репозиторий.

## Отдельная папка продаж и очистка

Рабочее хранилище имеет структуру:

```text
data.json                        # справочники, закупки, указатели на дни
sales/
  2026-09-12/
    <revision>.json               # продажи одного дня
```

В локальном режиме эти файлы находятся в `.barbar-data/`; на Netlify это ключи в Netlify Blobs, а не файлы Git. Локальные файлы дополнительно содержат служебную версию ETag. Скачивание дня из интерфейса выдаёт чистый массив продаж `2026-09-12.json`.

Запись сначала создаёт неизменяемую версию дня, затем атомарно обновляет указатель в `data.json`, после чего удаляет предыдущую версию файла. Условная запись по ETag предотвращает потерю обновлений при работе с разных устройств. Повтор одной операции не создаёт вторую продажу.

В **«Файлы и копии»** можно скачать каждый день отдельно и удалить все продажи **строго раньше выбранной даты**. Перед подтверждением показывается количество дней и записей, доступна полная резервная копия. После очистки:

- подробные продажи и их ежедневные файлы удалены;
- суммарный расход и его стоимость остаются в компактном остатке;
- количество и стоимость текущих запасов не меняются;
- операции в очищенном периоде закрыты;
- отчёты за удалённые дни недоступны, о чём интерфейс сообщает;
- восстановление возможно из полной резервной копии.

Сбой после публикации нового указателя может оставить непривязанную старую версию файла; операция при этом уже сохранена. Ошибки удаления известных старых файлов отражаются предупреждением. При недоступности хранилища не подтверждаем запись как успешную.

В этой версии рабочий JSON-снимок ограничен 3 МБ, чтобы укладываться в синхронные ответы Functions. При приближении к пределу нужно выгружать резервные копии и чистить старую историю. Для большого многолетнего учёта с множеством касс стоит перенести журнал в полноценную базу данных.

## Структура проекта

```text
src/barbar/
  data/alcohol.json              # начальный каталог ингредиентов
  data/cocktails.json            # исходное меню и продажные цены
  data/sales/initial.json        # пустая начальная история
  model.ts                      # расчёты, валидация, списание, очистка
  store.tsx                     # обмен с Node API, обновление устройств
  pages/                        # продажи, склад, меню, отчёты, файлы
  style.css                     # адаптивное оформление
netlify/functions/              # серверные маршруты входа и API
netlify/lib/                    # сессии, операции, файловое хранилище
server/local-api.ts             # локальный Node-сервер и файловый адаптер
public/barbar/                  # логотип и изображения
```

## Проверки

```sh
npm test                       # расчёты, API, конкуренция, очистка
npm run build                  # TypeScript + production React build
npm run dev                    # отдельный терминал, порт 4001
npm run test:e2e                # браузерные сценарии; требуется Google Chrome
```

Браузерные тесты используют изолированные данные и не создают закупки или продажи в рабочем локальном баре. Вход дополнительно проверяется через настоящий локальный Node.js API.
